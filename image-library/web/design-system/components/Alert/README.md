Alert 傳達需要立刻處理的關鍵資訊，最多三個按鈕。

**使用者提供**：`title`、`message`、`actions`（`{label, role: 'default'|'cancel'|'destructive', onPress}`，最多三個）、`icon`（macOS App 圖示）、`textField`、`suppression`（macOS「不要再詢問」）、`presented`（加上遮罩）。

## 何時使用（HIG Alerts）
- 少用。只是告知資訊時改用情境內的提示。
- 常見且可復原的破壞性動作（刪郵件、刪檔案）不跳 Alert；**不常見又無法復原**的破壞性動作才跳。
- 不要在 App 啟動時跳 Alert。
- iOS 中，針對使用者刻意發起的動作所提供的選擇，改用 ActionSheet。

## 文字
- 標題清楚具體，不超過兩行；不要用「錯誤」「發生錯誤 329347」這類通用標題。完整句子用句子式並加標點；片語不加結尾標點。
- 說明文字只在有幫助時才加，簡短完整。不要解釋按鈕的作用。
- 按鈕標題一到兩個字（詞），描述結果；偏好與內文呼應的動詞（刪除、清除、退出）。避免「是／否」；「好」只用於純資訊。取消按鈕一律叫「取消」。

## 按鈕順序（本元件自動排列）
- 兩個按鈕並排：取消在前緣、預設在後緣。三個按鈕堆疊：預設在最上、取消在最下。
- 破壞性樣式只給「使用者並非刻意選擇」的破壞性按鈕；刻意選擇的（例如「清空垃圾桶」）確認鈕不用破壞性樣式。
- 有破壞性動作就要有取消；取消絕不是預設按鈕；希望人讀內容時不要設預設按鈕。
- 鍵盤 Escape（或 ⌘.）等同取消。
