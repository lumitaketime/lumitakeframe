取得設計系統的方式：在 Claude Code 執行 `/design-sync`，或用 Artifact 工具讀取上面的連結，把 `project/tokens.json`、`project/README.md`、`project/components/` 取回專案。兩種方式都不可用時，請告知本人，由本人匯出檔案提供。

設計系統的元件包是 React 18（全域名稱 `window.LiquidGlass`）。開工前先確認 Lumitake 前端使用的框架：

- 前端是 React：直接使用元件包裡的元件。
- 前端不是 React：只取用 `tokens.css` 與 `bundle.css` 的樣式，依各元件的 README 重寫成前端現有框架的元件，外觀與行為要一致。

設計系統是依 Apple 公開的設計規範整理的非官方網頁實作。數值以設計系統的 token 為準，不要寫死色碼。

## 視窗結構

單一主視窗，分成五個區域；只有側邊欄與工具列上的控制項是玻璃。

&#91;embedded content: 視窗分區 · 側邊欄、工具列、內容區、資訊欄、狀態列\]

視窗最小 960×600。視窗寬度小於 1100 時資訊欄自動收起；小於 800（手機瀏覽器）時側邊欄收成抽屜，工具列只留檢視切換與搜尋。側邊欄寬度可拖曳（200－320），可用 ⌘ ⌃ S 收合。

## 導覽架構

側邊欄分四組，是整個 App 唯一的主要導覽；硬碟不論是否接上都會列出。

| 群組 | 項目 | 這一頁做什麼 |
| --- | --- | --- |
| 資料庫 | 所有檔案 | 跨所有硬碟瀏覽，五種檢視模式 |
| 資料庫 | 照片 | 沿用 Lumitake 的歷史時間軸 |
| 資料庫 | 重複項目 | 重複檔案與重複資料夾，選擇保留哪一份 |
| 資料庫 | 待刪除 | 已標記、等本人確認的項目；NTFS 硬碟在此匯出清單 |
| 類型 | 影片、照片、文件、音樂、壓縮檔、其他 | 跨硬碟的類型篩選，每項顯示檔案數與總大小 |
| 硬碟 | 每顆硬碟一列 | 該硬碟的內容；顯示名稱、容量條、連線狀態、上次掃描時間 |
| 智慧資料夾 | 已儲存的搜尋 | 重新執行該搜尋 |

側邊欄底部固定兩項：「掃描進度」（有工作進行時顯示進度環）與「設定」。

硬碟列的三種狀態要能一眼分辨，不能只靠顏色：

- **已連線**：實心硬碟圖示，名稱為主要文字色
- **未連線**：空心硬碟圖示，名稱為次要文字色，後方加「未連線」文字
- **掃描中**：圖示旁顯示進度環與百分比

在未連線硬碟上的檔案仍可瀏覽與搜尋；需要讀取檔案內容的動作（開啟、預覽原檔）停用，並顯示「請接上『硬碟名稱』」。

## 五種檢視模式

「所有檔案」、類型、硬碟三類頁面共用五種檢視，用工具列中央的分段控制項切換；切換時保留目前所在的資料夾與選取的項目，每個位置記住上次用的檢視。

| 檢視 | 快捷鍵 | 規格 | 互動 |
| --- | --- | --- | --- |
| 圖像 | ⌘ 1 | 縮圖格狀，縮圖大小用工具列滑桿調整（64－256）；照片影片顯示縮圖，其他顯示類型圖示 | 按兩下進入資料夾或開啟檔案 |
| 列表 | ⌘ 2 | 欄位：名稱、大小、類型、修改日期、所在硬碟、副本數；列高 28 | 按欄位標題排序，欄寬可拖曳，欄位可顯示或隱藏 |
| 直欄 | ⌘ 3 | 一層一欄向右展開，每欄寬 220，可拖曳；最右欄顯示選取項目的預覽 | 方向鍵上下移動、左右進出層級 |
| 樹狀 | ⌘ 4 | 縮排的資料夾樹，每列右側顯示總大小與佔上層比例的細條；有副本的資料夾加「另有 2 份」標籤 | 按三角形展開；⌥ 加按展開整個子樹 |
| 佔比 | ⌘ 5 | 矩形方塊圖，面積代表大小、顏色代表檔案類型；方塊間距 2，小於 24×16 的方塊不顯示文字 | 按一下選取，按兩下進入下一層，路徑列點上層返回；滑鼠停留顯示名稱與大小 |

五種檢視共同的規則：

- **選取**：按一下單選，⌘ 加按多選，⇧ 加按連續選取；選取的項目用 `selection` 反白。
- **空白鍵**：開啟快速預覽。硬碟未連線時顯示縮圖與目錄資訊，不讀原檔。
- **右鍵選單**：在 Finder 中顯示、拷貝路徑、顯示所有副本、標記為待刪除、取得資訊。不提供搬移與改名。
- **路徑列**：內容區上方顯示「硬碟 › 資料夾 › 子資料夾」，每一段都可以按。
- **副本標示**：在其他硬碟也有相同內容的檔案或資料夾，顯示「重複」圖示與份數。

## 主要畫面規格

### 硬碟總覽

按側邊欄「硬碟」群組標題進入，每顆硬碟一張卡片。

- 卡片內容：名稱、格式（APFS、exFAT、NTFS）、已用與總容量、依類型分色的容量條、檔案數、上次掃描時間、連線狀態
- NTFS 硬碟加「唯讀」標籤
- 動作：掃描、重新掃描、停止、從目錄移除（只刪目錄紀錄，不動硬碟，需確認）
- 新接上、還沒掃過的硬碟：卡片顯示「加入目錄」按鈕，不自動開始掃描

### 搜尋

搜尋欄在工具列右側，⌘ F 聚焦。

- 輸入時即時顯示結果，延遲 200 毫秒再查詢
- 搜尋欄下方一列篩選標籤：範圍（目前位置、所有硬碟）、類型、年份、大小、所在硬碟
- 沿用現有的 `type:`、`ext:`、`year:`、`root:` 語法；篩選標籤是這些語法的圖形介面
- 全文檢索的結果顯示命中段落，關鍵字以粗體標示，不要只用顏色
- 可把目前的搜尋「儲存為智慧資料夾」

### 重複項目

上方分段控制項切換「重複資料夾」與「重複檔案」，預設顯示資料夾。

- 每一組一列：名稱、每份大小、份數、可釋出的空間；預設依可釋出空間由大到小排序
- 展開後列出每一份所在的硬碟與路徑，每份前面一個「保留」核取方塊
- 至少要保留一份：只剩一份被勾選時，該核取方塊不能取消
- 「標記其餘為待刪除」按鈕，需確認；只做標記，不刪除檔案
- 還沒完整比對內容的組別加「待確認」標籤，不能標記為待刪除
- 頁面頂端顯示總計：共幾組、可釋出多少空間

### 待刪除

- 依硬碟分組列出已標記的項目，可個別取消標記
- 一般硬碟：「移到垃圾桶」按鈕，跳出警示視窗，標題寫明數量與大小，按鈕為「移到垃圾桶」與「取消」
- NTFS 硬碟：按鈕改為「匯出清單」，產生文字檔存到 Mac，不寫入該硬碟

### 掃描進度

- 每個工作一列：硬碟名稱、階段（建立目錄、比對內容、抽取文字、AI 分析）、進度條、已處理與總數、預估剩餘時間
- 每列有「暫停」與「停止」；硬碟被拔掉時狀態改為「已中斷，接上後可繼續」，不顯示為錯誤
- 工作清單要存進資料庫，關掉 App 再開仍然在
- 選單列圖示在有工作時常駐，按一下顯示相同的進度摘要

### 設定

左側分類、右側內容的設定視窗。

| 分類 | 內容 |
| --- | --- |
| 一般 | 外觀（跟隨系統）、介面語言、啟動時開啟的頁面 |
| 目錄 | 目錄存放位置（可改到其他磁碟）、目錄大小、略過的資料夾 |
| 掃描 | 同時掃描的硬碟數、只在夜間執行的時段、掃描後是否比對內容 |
| 搜尋與語言 | 已安裝的語言包、安裝或移除語言包 |
| AI | 模型狀態與下載、掃描後自動分析（預設關閉） |
| 連線 | 沿用 Lumitake 現有的登入與手機連線設定 |

### 首次使用

三個步驟，每步一個畫面：歡迎與「只讀不寫、永不自動刪除」的承諾→選擇目錄存放位置→接上第一顆硬碟並加入目錄。按鈕用詞依序為「開始使用」「繼續」「完成」，每步都可以略過。

## Liquid Glass 使用規則

玻璃只用在浮在內容上方的控制層；內容本身一律不透明。這同時是設計規範，也是捲動流暢的前提。

| 區域 | 材質 | 說明 |
| --- | --- | --- |
| 側邊欄 | 玻璃（regular） | 浮動面板，與視窗邊緣留 8，圓角 `radius-lg` |
| 工具列的按鈕群組、搜尋欄 | 玻璃（regular） | 膠囊形，浮在內容上方 |
| 選單、彈出視窗、警示視窗、表單 | 玻璃（regular） | 暫時性的層，用 `shadow-popover` |
| 快速預覽上的控制鈕 | 玻璃（clear） | 只用在照片與影片上方；底下太亮時加 `glass-dim` |
| 列表、縮圖格、樹狀、佔比圖、資訊欄內容 | 不透明 | 用 `window-bg`、`control-bg`，不加陰影 |
| 資料列、卡片、標籤 | 不透明 | 不要用玻璃 |

網頁上的玻璃由四個部分組成，數值全部取自 token：

```css
/* 變數名稱以設計系統產生的 tokens.css 為準 */
.glass {
  background: var(--glass-regular);            /* 填色 */
  backdrop-filter: blur(var(--blur-glass)) saturate(180%); /* 模糊 */
  box-shadow: var(--shadow-rim), var(--shadow-glass);      /* 邊緣高光與浮起的陰影 */
  border: 0.5px solid var(--glass-edge);       /* 細邊 */
}
@media (prefers-reduced-transparency: reduce) {
  .glass { background: var(--elevated-primary); backdrop-filter: none; }
}
```

實作時要遵守：

1. **模糊層不跟著捲動**：玻璃元素位置固定，捲動的是它底下的內容。不要在捲動容器裡的每一列上用 `backdrop-filter`。
2. **同一個畫面最多兩層玻璃重疊**：例如側邊欄加上一個選單。玻璃不疊在玻璃上。
3. **內容延伸到玻璃下方**：內容區捲動時從工具列底下經過，工具列不墊實心色塊，改用捲動邊緣的漸層遮罩。
4. **玻璃上不替文字或符號上色**：只有主要動作的按鈕背景用 `accent`，一個畫面一個。
5. **形狀**：獨立按鈕、搜尋欄、工具列群組用膠囊（`radius-capsule`）；內層圓角等於外層圓角減去兩者的間距。
6. **動態**：按住玻璃按鈕時放大約 4% 並增亮；`prefers-reduced-motion` 開啟時取消位移與縮放，改用淡入淡出。
7. **四個主題都要能用**：淺色、深色、淺色增強對比、深色增強對比；跟隨系統設定，不提供 App 專屬的外觀開關。

網頁的玻璃是近似效果，沒有系統原生材質的折射與動態高光；不要為了模仿而加上 SVG 折射濾鏡，那會拖慢捲動。

Tauri 視窗建議使用覆蓋式標題列，讓工具列與紅綠燈按鈕同一列；工具列的空白處要能拖曳視窗。請先確認目前的 Tauri 版本支援的設定方式。

## 動態

動態以 Liquid Glass 設計系統為準：時間與曲線都取自設計系統元件實際使用的值，不另外發明。動畫只做兩件事：說明「東西從哪裡來、到哪裡去」，以及讓人知道「操作有被接收」。純裝飾的動畫不做。

時長與曲線（樣式用變數，程式用 `lib/motion.js` 的 `DUR`、`EASE`，兩邊數值相同）：

| 變數 | 值 | 用在哪裡 |
| --- | --- | --- |
| `--dur-fast` | 150 毫秒 | 滑過、按下時的亮度與透明度；浮層關閉 |
| `--dur-quick` | 200 毫秒 | 按下時的縮放、小元件位移、展開與收合 |
| `--dur` | 250 毫秒 | 背景與顏色變化；選單、彈出視窗、對話框出現 |
| `--dur-move` | 300 毫秒 | 開關與分段控制的滑塊、進度條 |
| `--dur-slow` | 350 毫秒 | 大片玻璃、側邊欄、資訊欄、抽屜 |
| `--ease` | `ease` | 顏色、透明度、一般變化 |
| `--ease-out` | 平滑減速，不回彈 | 大面積的滑入與滑出 |
| `--spring-soft`、`--spring`、`--spring-press` | 回彈由小到大 | 只用在玻璃控制項：分段控制的滑塊、開關、按下的玻璃按鈕 |

各種情況怎麼動：

| 情況 | 做法 |
| --- | --- |
| 按下控制項 | 一般按鈕稍微變暗；玻璃按鈕放大約 4% 並增亮（`--spring-press`）；無框按鈕降低透明度 |
| 換頁、切換分頁、切換檢視模式 | 直接換，不做整頁淡入或滑動 |
| 選單、彈出視窗 | 從觸發的按鈕位置出現：淡入加很小的放大（`--dur`）；關閉只淡出（`--dur-fast`） |
| 對話框、表單 | 從中間淡入加輕微放大，背景變暗；關閉比出現短 |
| 側邊欄、資訊欄、抽屜 | 滑進滑出（`--dur-slow`、`--ease-out`），內容區跟著讓位 |
| 清單、縮圖格、樹狀圖 | 捲動與載入時不做進場動畫；項目直接出現 |
| 照片開啟與關閉 | 從縮圖的位置放大成全螢幕，關閉時縮回原位 |
| 載入中 | 用設計系統的 `ProgressIndicator`；超過 300 毫秒才顯示 |
| 捲到底的回彈 | 只在觸控裝置保留；Mac 上交給系統 |

規則：

1. 離場比進場短；同一種元件在整個 App 用同一種動法。
2. 只動 `transform` 與 `opacity`；不對寬高、位置、模糊做動畫，那會拖慢畫面。
3. 回彈曲線只用在玻璃控制項，內容與大面積面板不回彈。
4. 動畫進行中不擋操作：可以立刻再按、再捲動。
5. 系統開啟「減少動態效果」時，位移與縮放一律改成淡入淡出，重複的動畫放慢或停止。
6. 樣式與程式裡不寫死毫秒數與曲線，`pnpm check` 會檢查。唯一的例外是不停重複的載入指示。

## 設計 token 對照

所有顏色、字級、間距、圓角都用 token 名稱取值；下表列出 Re'memor 最常用的，完整清單在設計系統的 `tokens.json`。

| 用途 | token | 淺色／深色 |
| --- | --- | --- |
| 視窗背景 | `window-bg` | #ececec／#323232 |
| 列表、表格內部 | `control-bg` | 見 tokens.json |
| 主要文字 | `label-primary` | #000000／#ffffff |
| 次要文字 | `label-secondary` | 見 tokens.json |
| 停用的項目 | `label-tertiary` | 見 tokens.json |
| 強調色、選取、連結 | `accent`（指向 `system-blue`） | #0088ff／#0091ff |
| 選取列的文字 | `on-accent` | #ffffff |
| 破壞性動作 | `destructive`（指向 `system-red`） | 見 tokens.json |

| 玻璃細邊 | `glass-edge` | #0000001f／#ffffff29 |
| 鍵盤焦點環 | `focus-ring` | 3px 實色 |

| 類別 | token | 值 | 用在 |
| --- | --- | --- | --- |
| 字級 | `mac-body` | 13 | 內文、列表、按鈕（macOS 預設） |
| 字級 | `mac-caption` | 10 | 最小字級，不可再小 |

## 狀態、文字與無障礙

每個畫面都要設計五種狀態，不能只做「有資料」的樣子。

| 狀態 | 表現 | 例子 |
| --- | --- | --- |
| 空白 | 說明下一步，附一個按鈕 | 「還沒有硬碟。接上硬碟後加入目錄。」加「加入硬碟」按鈕 |
| 載入中 | 超過 300 毫秒才顯示進度；列表用灰色佔位列 | — |
| 無結果 | 說明原因與可以調整的地方 | 「找不到『預算』。試試搜尋所有硬碟。」 |
| 硬碟未連線 | 內容照常顯示，讀檔動作停用並說明 | 「請接上『備份 B』以開啟這個檔案。」 |
| 錯誤 | 放在問題旁邊，說明怎麼修正，不責怪 | 「無法讀取這個資料夾。請確認硬碟仍然接著。」加「再試一次」 |

文案規範（完整版在設計系統 README 的「內容原則」）：

- 按鈕用動詞：「掃描」「加入目錄」「移到垃圾桶」；取消一律叫「取消」
- 不用「我們」，少用「你的」：寫「無法載入內容」
- 警示視窗的標題要具體：「要把 128 個項目移到垃圾桶嗎？」，不寫「確認」或「錯誤」
- Mac 上說「按一下」，不說「點一下」
- 中文與英文、數字之間加半形空格：「共 1,284 個項目」；刪節號用「…」
- 介面不使用 emoji，符號一律用設計系統的 `Icon`
- 大小用 KB、MB、GB、TB，最多一位小數；日期用「2026/11/10」

無障礙與鍵盤：

- 所有功能都能只用鍵盤完成；Tab 在側邊欄、工具列、內容區、資訊欄之間移動，方向鍵在區域內移動
- 鍵盤焦點一律顯示 `focus-ring`，用 `:focus-visible`
- 純圖示按鈕要有 `aria-label`；列表、樹狀、格狀用對應的 ARIA 角色（listbox、tree、grid）
- 文字對比至少 4.5:1，控制項邊框與圖示至少 3:1；系統開啟「增加對比」時切換到增強對比主題
- 尊重「減少動態效果」與「減少透明度」
- 常用快捷鍵：⌘ 1－5 切換檢視、⌘ F 搜尋、空白鍵預覽、⌘ I 資訊欄、⌘ , 設定、⌘ ↑ 回上層

多語言：

- 介面文字全部抽到語言檔，程式裡不直接寫中文；預設提供繁體中文與英文
- 數量、日期、大小用語系格式化，不要用字串拼接
- 版面要容得下比中文長 40% 的文字，按鈕與標籤不寫死寬度

## 前端架構與效能

沿用 Lumitake 現有的前端框架與建置工具，不換框架；下面是新增部分要遵守的結構。動手前先向本人說明現有前端的結構與預計的改動。

| 層 | 負責 | 規則 |
| --- | --- | --- |
| 樣式 | token 與元件樣式 | 設計系統的 `tokens.css` 是唯一來源；不在元件裡寫色碼或數值 |
| 基礎元件 | 按鈕、列表、選單等 | 來自設計系統，或依其 README 重寫；不含業務邏輯 |
| 檢視元件 | 圖像、列表、直欄、樹狀、佔比 | 五種檢視吃同一份資料介面（項目清單、選取、排序），可互相替換 |
| 頁面 | 所有檔案、類型、硬碟、重複、待刪除、設定 | 組合檢視元件與資料，不直接呼叫 API |
| 資料層 | 呼叫引擎 API、快取、分頁 | 所有 API 呼叫集中在這一層 |
| 語言檔 | 介面文字 | 每種語言一個檔案 |

引擎 API 的原則（端點名稱依現有慣例命名）：

- **分頁或視窗化**：列出資料夾內容時只回傳請求的範圍（起始位置與筆數），另回傳總數；不一次回傳整個資料夾
- **排序與篩選在資料庫做**：不把整張表讀進 Python 再計算
- **資料夾大小用預先算好的值**：來自「資料夾」表，不臨時加總
- **佔比圖一次只取兩層**：目前層與下一層，小於總量 0.5% 的項目合併成「其他」
- **進度用推送**：掃描進度用伺服器推送或長連線，不要每秒輪詢整份清單

效能門檻，每個階段結束前用測試資料實測：

| 項目 | 門檻 | 測試條件 |
| --- | --- | --- |
| 列表與圖像檢視捲動 | 維持 60 fps，無明顯掉幀 | 單一資料夾 100,000 個項目，M1 Pro |
| 畫面上的 DOM 列數 | 不超過可見列數加 20 | 同上 |
| 切換檢視 | 200 毫秒內完成 | 同上 |
| 進入資料夾 | 300 毫秒內顯示第一屏 | 目錄共 1,000,000 個檔案 |
| 搜尋 | 500 毫秒內顯示第一批結果 | 同上 |
| 佔比圖 | 500 毫秒內畫出 | 最多畫 500 個方塊 |
| App 啟動 | 3 秒內可操作 | 硬碟全部未連線 |

達成方式：

- 列表、圖像、樹狀、直欄都用虛擬捲動，只畫看得到的列；列高固定，位置用 `transform`
- 佔比圖用 Canvas 或 SVG 繪製，不用上萬個 DOM 元素；版面計算放在背景執行緒
- 縮圖延遲載入，用掃描時產生的小縮圖，不載入原檔
- 捲動期間不觸發版面重算；用 `requestAnimationFrame` 合併更新
- 測試資料用腳本產生（建立假的目錄紀錄），不需要真的硬碟

## 開發順序與驗收

介面分六步做，每一步完成後都能實際操作，並由本人確認後再進下一步；引擎的工作（三張新表、掃描所有檔案類型）依規劃書的階段進行，介面跟在引擎之後。

| 步驟 | 內容 | 需要的引擎功能 | 完成標準 |
| --- | --- | --- | --- |
| 1 | 設計基礎：取回設計系統、套用 token、四個主題、基礎元件、語言檔機制 | 無 | 現有畫面改用 token 後外觀正常；切換系統深淺色與增加對比都正確 |
| 2 | 視窗外框：側邊欄、工具列、路徑列、資訊欄、狀態列 | 硬碟表 | 側邊欄列出所有硬碟與三種狀態；玻璃只出現在控制層 |
| 3 | 列表與圖像檢視、類型篩選、硬碟總覽 | 所有檔案表、資料夾表 | 10 萬個項目捲動達到效能門檻；硬碟拔掉仍可瀏覽 |
| 4 | 直欄、樹狀、佔比檢視 | 資料夾總大小 | 五種檢視可切換並保留位置與選取 |
| 5 | 重複項目、待刪除、掃描進度 | 內容比對、重複資料夾偵測 | 至少保留一份的規則有效；NTFS 硬碟只能匯出清單 |
| 6 | 搜尋與篩選標籤、設定、首次使用、App 圖示與選單列圖示 | 全文檢索 | 命中段落正確顯示；圖示六種外觀到位 |

每一步交付前的檢查清單：

- [ ] 沒有寫死的色碼、字級、圓角、動畫時間與曲線；全部來自 token
- [ ] 動態符合「動態」一節的規則，並在「減少動態效果」開啟時看過
- [ ] 淺色、深色、兩個增強對比主題都看過
- [ ] 空白、載入中、無結果、硬碟未連線、錯誤五種狀態都有
- [ ] 只用鍵盤可以完成所有操作，焦點環清楚可見
- [ ] 介面文字都在語言檔，繁體中文與英文都有
- [ ] 用 10 萬個項目的測試資料量過效能門檻，並回報數字
- [ ] 沒有任何動作會寫入被掃描的硬碟；刪除一律先經本人確認
- [ ] 原有測試全部通過，新功能有對應的測試
- [ ] 實際開啟 App 操作過，並附上截圖給本人看
