# Re'memor 規劃書

Nov 10, 2026 · @Clarence

## 專案目標

以現有的 **Lumitake Library**（0.19.2）為基礎擴充，把從國中累積至今、散落在 8 顆外接硬碟（約 80T）的檔案，整理成一份**硬碟拔掉也能查**的完整目錄，找出重複的備份，並用離線 AI 讀懂內容、以中文搜尋。

要解決的問題：

- 檔案在某顆硬碟裡，但不知道是哪一顆
- 同一批資料被備份很多次，空間被重複檔案佔滿
- 看不出空間被哪些資料夾、哪種檔案吃掉
- 只能用檔名找，無法用內容或畫面描述找

長期目標：在「知道自己有什麼」這件事上比 Finder 更好用；介面要能面向大眾：好用、穩定、專業、美觀。目前最急迫的是管理、整理、編列目錄；連網沿用 Lumitake 現有功能，暫不擴充；保留日後移植 Windows 的可能。

## 核心原則

1. **永不自動刪除**：軟體只標記、建議，或移到「待刪除」資料夾，每一次刪除都要本人確認。這些是十幾年的檔案，弄錯救不回來。
2. **資料不出家門**：掃描、AI 模型、資料庫、索引都在自己的電腦上，不上傳任何雲端。
3. **面向大眾**：好用、穩定、專業、美觀；不懂技術的人也能上手。
4. **流暢度**：捲動與切換要和 Finder 一樣順；畫面只畫出看得到的部分，每個階段都用十萬個檔案實測。
5. **多語言**：中文與英文為預設，其他語言以語言包安裝。
6. **可中斷、可接續**：大硬碟掃描以「夜」為單位，隨時拔掉，下次接上從中斷處繼續。
7. **只讀不寫硬碟**：掃描時不修改硬碟上的任何檔案。
8. **AI 標注是建議**：本人可以修正，軟體記住修正，下次照本人的習慣分類。

## 功能規劃

所有功能都建立在**目錄資料庫**上：每顆硬碟掃過一次，之後拔掉也能瀏覽與搜尋，軟體會告訴你檔案在哪顆硬碟、哪個資料夾。「Lumitake 現況」依安裝檔裡的模組名稱判斷，細節待在 Code 看原始碼確認。

| 功能 | 內容 | Lumitake 現況 |
| --- | --- | --- |
| 硬碟目錄 | 記錄所有檔案的檔名、大小、日期、資料夾結構；目錄存放位置可自選（Mac 內建硬碟或常接的 SSD） | 部分：已有掃描器與資料庫，目前針對照片影音 |
| 照片時間軸 | 照片影音依拍攝時間排成連貫的歷史時間軸 | 已有 |
| 直欄檢視 | Finder 經典的一層層往下鑽 | 新做 |
| 圖像檢視 | 縮圖格狀，看照片、影片、文件封面 | 部分 |
| 列表檢視 | 依大小、日期、類型排序 | 新做 |
| 樹狀圖 | 一層層展開，顯示各資料夾總大小與「其他硬碟也有副本」的標示 | 新做 |
| 佔比圖 | 矩形方塊圖，面積代表大小、顏色代表類型，可點進下一層 | 新做 |
| 類型篩選 | 跨所有硬碟列出全部影片、JPG、PDF 等，再按年份、大小、所在硬碟細分 | 新做 |
| 壓縮檔內容 | 不解壓，記錄 ZIP、RAR、7z 裡的檔案清單 | 新做 |
| 重複檔案 | 用內容指紋比對，與檔名無關；先用大小篩選以節省時間 | 待確認 |
| 重複資料夾 | 偵測整個資料夾被備份多次 | 新做 |
| 文件文字與 OCR | 抽取 PDF、Word、PPT、電子書文字；截圖與掃描檔做文字辨識 | 新做 |
| 音樂 | 讀取 FLAC、MP3 的曲名、演出者、專輯 | 新做 |
| 照片影片辨識、人臉 | 辨識畫面內容、人臉 | 已有 |
| 中文搜尋 | 中英文全文檢索，可安裝日、韓、德、法等語言包；也能用描述找，例如「國中時的自然科報告」 | 部分：已有圖像搜尋；文件全文檢索新做 |
| AI 分類標注 | 規則先分七八成，再以資料夾為單位標注，只有需要讀懂的文件才交給模型 | 待確認 |
| 整理與清理 | 重複檔案由本人選擇保留哪份；NTFS 硬碟改產生「待刪除清單」 | 部分：已有檔案操作與整理模組 |
| 背景工作 | 掃描、分析排程在背景執行，可中斷接續 | 已有 |
| 家用伺服器、手機存取 | 沿用 Lumitake 現有的登入與連線，暫不擴充 | 已有 |
| Spotlight 整合 | 重要項目放進 Spotlight，並提供快捷操作 | 新做 |

前期不取代 Finder 的複製、搬移、改名。核心穩定後，再加上「整理建議、一鍵搬移、可復原」。

## 全文檢索

中文與英文為預設，其他語言以語言包安裝；所有硬碟共用一個索引，硬碟拔掉也能搜到內容。

| 項目 | 做法 |
| --- | --- |
| 搜尋索引 | SQLite 內建全文檢索（FTS5），結果顯示命中段落、檔案位置與所在硬碟 |
| 中文、日文 | 字與字之間沒有空格，需專用斷詞，否則「自然科報告」搜不到 |
| 韓文 | 需專用斷詞 |
| 英、德、法文 | 依空格分詞，並處理大小寫與詞形變化（report 與 reports） |
| 掃描檔與截圖 | 文字辨識（OCR）也要對應語言 |
| 語言包 | 斷詞規則加 OCR 語言，在設定中安裝或移除 |
| 跨語言搜尋 | 由語意搜尋模型負責，用中文「預算表」也能找到英文 budget.xlsx |

## 離線 AI 的用途

三種離線模型各管一件事，全部在本機執行，沒有網路也能用。

| 模型 | 做什麼 | 例子 |
| --- | --- | --- |
| 圖像模型（Lumitake 已有） | 看懂照片與影片畫面、人臉 | 搜「海邊的夕陽」 |
| 語意搜尋模型 | 把文字轉成「意思」，跨語言、跨用字找檔案 | 搜「預算」也找得到寫著「經費」的文件 |
| 小型語言模型 | 讀文件後寫摘要、分類標注、提出整理建議、用問句找檔案 | 「這份是國中自然科報告」；「去年音樂會的節目單在哪顆硬碟？」 |

小型語言模型最吃效能，只處理真正需要讀懂的文件；M1 Pro 跑小型模型，日後的 M5 Pro 可換較大的模型。

## 技術架構

沿用 Lumitake 的三層結構：Tauri 外殼、網頁介面、Python 引擎。引擎和介面分開，所以同一個軟體既能單機使用，也能讓 M1 Pro 當伺服器、其他裝置連進來。

&#91;embedded content: 雙機架構 · M1 Pro 伺服器與各裝置\]

主要以單機使用：M1 Pro 或 M5 Pro 接上硬碟即可完整運作。連網沿用 Lumitake 現有功能、暫不擴充；引擎與介面分開，日後要讓 M1 Pro 當家用伺服器時不必重寫。

| 層 | 技術 | 現況 |
| --- | --- | --- |
| 外殼 | Tauri（Rust） | 已有 |
| 介面 | 網頁＋ PWA | 已有照片時間軸；檔案檢視模式新做 |
| 引擎 | Python＋ FastAPI | 已有 |
| 目錄資料庫 | SQLite | 已有 |
| AI 模型 | ONNX Runtime | 已有 |
| 照片中繼資料 | exiftool | 已有 |
| 文件文字、OCR、壓縮檔、音樂標籤 | 待選套件 | 新做 |
| 效能關鍵部分（掃描、算指紋） | 逐步改寫為 Rust | 長期 |
| 全文檢索 | SQLite FTS5＋各語言斷詞 | 新做 |
| 語意搜尋、小型語言模型 | 本機執行的離線模型 | 新做 |

Windows 移植：Tauri、Python、ONNX、網頁介面都能在 Windows 執行，只需處理路徑、外接硬碟偵測等少數平台差異。若日後想要真正的 Liquid Glass，可另做 Swift 原生介面連到同一個引擎。

## 開發階段

在 Lumitake 的專案裡開分支開發，圖庫在主線上照常使用；每個階段完成後都能實際使用，穩定了再合併回主線。

&#91;embedded content: 開發階段 · 準備加五個階段\]

照片影片辨識、人臉、背景工作、登入與連線 Lumitake 已有，不另列階段；連線功能暫不擴充。每個階段結束時先用自己的硬碟實測，確認沒問題再進入下一階段。

## 介面與設計系統

介面用網頁技術，目標是 Finder 的流暢度加上 CleanMyMac 等級的精緻感；照片沿用時間軸，檔案提供五種可切換的檢視模式。

- 另建一套獨立的「Liquid Glass」設計系統，與現有的「Material Design 3」互不干涉
- Claude Design 的設計系統本身就是網頁，可以直接套用到介面，不必轉換
- 玻璃效果只用在側邊欄、工具列等固定區域；捲動的內容區保持乾淨，避免即時模糊拖慢捲動
- 列表與縮圖只畫出看得到的部分；縮圖在掃描時預先產生
- 若日後想要真正的 Liquid Glass 材質，可另做 Swift 原生介面接同一個引擎

## 限制與注意事項

| 項目 | 狀況 | 對策 |
| --- | --- | --- |
| 系統版本 | 目前 Mac 是 Sequoia；網頁介面不需要新系統 | 不必為本軟體升級；日後若做 Swift 原生介面，才需要 macOS 26 以上 |
| NTFS 硬碟 | Mac 只能讀不能寫 | 掃描、去重、搜尋都正常；清理時改產生「待刪除清單」，接到 Windows 或日後裝 NTFS 寫入工具處理 |
| 掃描時間 | 共 8 顆 USB 3.0／3.1 老硬碟（4 顆 16T、4 顆 4T，約 80T），每顆約每秒 150 MB；一顆接一顆全部讀完約 6 天 | 先用大小篩選，只讀大小相同的檔案；同時接 3～4 顆並行；可中斷接續，夜間執行 |
| 記憶體 16GB | M1 Pro 只能跑小型離線模型，一次一種；計畫購入的 M5 Pro 可負責較重的 AI 分析 | 規則優先、以資料夾為單位標注；影片語音轉文字延後 |
| 檔案量 | 可能數十萬到上百萬個檔案 | 不逐一交給 AI；Spotlight 只放重要項目 |
| 開發環境 | 沿用 Lumitake 的開發環境（Tauri、Python） | 在 Code 接續開發，由 Claude 一步一步帶 |

老硬碟長時間連續讀取有故障風險：第一次全面掃描前，先檢查每顆硬碟的健康狀態，並優先備份無可取代的檔案。

## 現有軟體比較

沒有一套軟體同時做到「離線硬碟目錄、資料夾級去重、中文內容搜尋」，這是自己開發的理由。

| 軟體 | 擅長 | 缺點 | 價格 |
| --- | --- | --- | --- |
| [NeoFinder](https://www.wfs-apps.de/PR/PR.NeoFinder.9.2.en.pdf) | 硬碟目錄，拔掉也能查，含壓縮檔內容 | 沒有 AI 辨識；實際用過，掃描很徹底，但介面與操作體驗很差 | 39 美元買斷 |
| DaisyDisk | 檔案佔比圖 | 只能看接著的硬碟 | 付費 |
| dupeGuru、Czkawka | 找重複檔案 | 看不出整個資料夾被重複備份 | 免費 |
| [Dhito](https://dhito.io/blog/best-local-ai-file-search-apps-mac-2026/) | 離線 AI 搜尋照片、影片、語音 | 文字搜尋模型為英文版；未說支援離線硬碟；不支援 PPT | 每月 4.99 美元 |
| [Fenn](https://dhito.io/blog/best-local-ai-file-search-apps-mac-2026/) | 離線 AI 搜尋、依內容改檔名、整理資料夾 | 未說支援離線硬碟與中文 | 249 美元買斷 |
| [macOS 27 Spotlight 與 Siri](https://sixcolors.com/post/2026/09/macos-27-golden-gate-review-bridging-the-tahoe-gap/) | 本機語意搜尋，免費內建 | 測試版、結果不穩定；硬碟拔掉就查不到；不處理重複檔案 | 內建 |
| Alfred | 快速啟動、自動化流程 | 靠 Spotlight 索引，沒有目錄、去重、AI 內容理解 | 付費 |
